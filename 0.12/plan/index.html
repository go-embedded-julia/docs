Plan

Milestones M0 to M7: contents, size and exit test; what the playground shows at each; how conformance is measured.

You are reading the documentation of an outdated version, whose text may no longer be accurate. Go to the latest version.

Status: in development. M0 (oracle harness), M1 (parser) and M2 (lowering) are done, released as v0.3.0 (2026-10-28) of go-embedded-julia/julia, against julia 1.12.6. M3 is in progress (v0.4.0, v0.5.0, v0.6.0, v0.7.0, v0.8.0, v0.9.0, v0.10.0, v0.11.0, v0.12.0); M4 to M7 are planned.

M2 in numbers: the lower package ports julia 1.12.6’s femtolisp front end (julia-syntax.scm, macroexpand.scm, ast.scm, match.scm). lower.NewState().Lower(ex) is Meta.lower of a macro-expanded top-level form, compared with julia field by field, modulo gensym numbering. It is identical on 53 997 of 53 997 forms of julia 1.12.6’s share/julia tree (base, Compiler, stdlib, test; 1191 of 1191 files), 124 of 124 lowering snippets, 48 of 48 hygienic-scope forms and 477 of 477 built expressions (error paths, rare heads); deparse matches julia --lisp on 119 of 119 forms and the front-end functions on 151 of 151 calls. Statement coverage is 100%. Lower refuses trees deeper than lower.MaxDepth (1000) and FuzzLower runs on every pull request. Known gap: a Float64 inside a lowering error message makes Lower return lower.ErrUnsupported.

M3 so far: core — Julia’s type objects, apply_type, and subtyping (a port of jltypes.c and subtype.c of 1.12.6, without intersection): identical to julia on 20 000 random pairs and 4 902 cases from test/subtype.jl; and method specificity (jl_type_morespecific, v0.4.0), identical to Base.morespecific on the same corpus. core/dispatch (v0.5.0): method tables with world ages, and the method a call with concrete argument types runs, with its static parameters: identical to julia’s which and dispatch environment on 9 000 calls over 1 500 random method tables (4 675 method choices, 1 968 with static parameters, 87 ambiguities). interp (v0.6.0 to v0.12.0): a port of julia 1.12.6’s src/interpreter.c that runs lowered code over Core (interp.New().NewSession().Eval(src), interp.Repr); v0.7.0 runs struct and abstract type definitions with julia’s default constructors (jl_ctor_def) and user-defined outer constructors, and calling a type dispatches on its constructors. v0.8.0 dispatches methods with where clauses with static parameters (e.g. f(x::T) where {T<:Integer} = T), through the TypeVar and UnionAll constructors of boot.jl:335-338, built in Go until boot.jl runs. v0.9.0 runs structs and abstract types with parameters (struct Q{T}, abstract type A{T}): Q(1) infers Q{Int64}, Q{Integer}(1) runs the inner constructor, a parameter no field constrains gets no outer constructor (as jl_ctor_def decides), constructor signatures keep the called type first as in julia’s one method table, and a type argument dispatches as Type{X}. v0.10.0 expands macros, a port of jl_expand_macros: a macro call runs the macro’s method with __source__ and __module__, hygiene goes through the hygienic-scope that lower resolves, nested and recursive macro calls are expanded in turn, quotes go through lower.Backquote, and a self-expanding macro raises StackOverflowError. v0.11.0 defines Core by julia 1.12.6’s own base/boot.jl, unmodified and embedded: vm.Boot() evaluates its 363 forms in Core, then runs post_boot_hooks (jltypes.c:3909-3968), so builtins raise boot.jl’s exception types and an error in an included file is a LoadError. After Boot, vm.CoreSession().Eval(src) runs code in Core; Boot is opt-in, and interp.New().NewSession().Eval is unchanged. Ported from julia’s C sources for it: the types jl_init_types creates (with real layouts for the IR nodes, GenericMemory, GenericMemoryRef and Array, plus AddrSpace and Core.CPU); module expressions and relative using .M / import ..M paths; the builtins _primitivetype, setfield!, invokelatest and invoke_in_world; getfield of types (DataType, TypeName, TypeVar, UnionAll, Union, Vararg) and of AST nodes; the intrinsics trunc_int, sext_int, zext_int, bitcast, shl_int, lshr_int and ashr_int; and ccall to Go shims keyed by the C function’s name (an unknown name is ErrUnsupported when the call runs). Display fixes, checked against julia 1.12.6: Float32 (1.0f0, NaN32), Char (escapes, malformed bytes, \u/\U) and nested modules (Main.L.B). include reads only VM.Sources (julia’s embedded sources by default), never the host’s filesystem, and an include that nests without end raises StackOverflowError. v0.12.0 runs julia 1.11+’s arrays: GenericMemory and GenericMemoryRef values with the builtins memorynew, memoryrefnew, memoryrefoffset, memoryrefget, memoryrefset! and memoryref_isassigned (builtins.c:1711-1856, genericmemory.c), Array{T,N}(undef, dims…) as boot.jl builds it, the overflow-checked intrinsics checked_[su]{add,sub,mul}_int, arrays and where-clause types shown as julia 1.12.6 shows them, and an Expr’s args as one Vector{Any}; VM.MaxMemoryElems bounds one allocation (interp.ErrMemoryLimit), the total is not bounded yet (#24). Not yet: atomic memory, and Base. Speed of arrays: not measured, there is no julia counterpart until programs index arrays through Base. Speed: Boot has no julia counterpart to measure against, since julia’s Core comes from its system image. Core has the built-in types, the exception and AST types of boot.jl and jltypes.c (with the QuoteNode, LineNumberNode and Expr constructors), 26 builtins (the six type-definition builtins and fieldtype are new in v0.7.0, _typevar in v0.8.0, _expr and _apply_iterate in v0.10.0) and the integer and float intrinsics. Checked: 97 Core-only programs show the same value in Go and julia 1.12.6; 100% statement coverage; fuzzed (FuzzEval). Not yet: type intersection, and with it the interference sets julia 1.12 uses to order matches; Base (+, println, a.b, and constructor arguments that need convert, macros that use esc or Base’s macros), splatting anything but a tuple or a simple vector (it calls Base.iterate), redefining a struct that has parameters (it needs Base.getproperty), const and atomic fields, arrays, finally, and the remaining builtins and intrinsics. Speed: subtyping is 1.37× slower than julia’s jl_subtype on one core (3.26 ms against 2.39 ms for the 20 000 pairs, best of 7 interleaved rounds, load 4.4–6.6, 2026-11-01), an open defect (#20); pooling the query environments (v0.9.1) halved the allocations (−51%); the speed of the interpreter against julia’s is not measured yet.

M1 in numbers: a Go port of JuliaSyntax 29ec5226f7b1, the version julia 1.12.6 ships. Tokens, green trees and Expr are identical to julia’s on 1191 of 1191 files of julia 1.12.6’s share/julia tree (base, Compiler, stdlib, test; 18.5 MB) and on 976 of 976 golden snippets. On one core the corpus parses in 0.98 s against 1.39 s for julia’s Meta.parseall (0.70x). Parsing is bounded (64 MiB, depth 4000) and fuzzed; coverage is 100%, tested natively on amd64/arm64/386, under qemu on riscv64/loong64/ppc64le/s390x/arm, compiled for every GOOS/GOARCH, and run on wasip1 under wazero. Known gap: on a few malformed inputs (import. .., import. ...x, 0:0:<) JuliaSyntax itself throws and julia falls back to the femtolisp parser, which is not ported: there ParseAll returns Expr(:error) and ParseAllLimits returns an error wrapping syntax.ErrParserFailed.

Effort is on the roadmap’s scale: S days, M weeks, L months, XL several months. M3 and M4 dominate; in total the effort is on the order of the rbgo effort, plus a parser and a lowering pass that rbgo did not need in this form.

Scope of the first version

In: all syntax JuliaSyntax parses; functions and multiple dispatch with parametric methods and where; keyword arguments; closures; struct and mutable struct; abstract and parametric types; Union, Nothing and Missing; tuples and named tuples; try/catch/finally; hygienic macros and @generated functions; string interpolation; broadcasting; comprehensions and generators; do blocks; modules; using and import of in-image modules; single-threaded tasks and Channel. From the standard library: LinearAlgebra (dense, over go-ndarray), Statistics, Random, Printf, Dates and Test. SparseArrays comes later.

Out: ccall to arbitrary user libraries (an error naming the symbol), llvmcall, @cfunction, parallel Threads.@threads (runs serially), Distributed, Pkg (packages ship in the image), and precompilation of user code.

How conformance is measured

Julia’s test suite is written with the Test standard library, and test/choosetests.jl lists the test names. The harness:

  1. runs each listed file under the reference julia and under the interpreter, one file per worker process with a timeout, each with a Test reporter that emits one JSON record per @test (file, line, expression, pass, fail, error or broken);
  2. compares records, not totals: a test passing in both, failing only in the interpreter (a defect), or failing in both (upstream), so that an equal count with different members is not read as parity;
  3. keeps a committed allowlist of files out of scope (precompile, loading, llvmcall*, threads, ccall to user libraries, spawn, cmdlineargs, compiler, jit), each with a reason, and reports the pass rate per remaining file;
  4. stores every failure found only in the interpreter as a regression test once it is fixed.

The differential oracles of each stage (M1 Expr, M2 CodeInfo, Random streams, printed show output) are stronger than the suite for the front end and are built first, which is why M0 comes before everything else.
